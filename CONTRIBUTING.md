# Contributing to Gurubodh

Start with the [project map](README.md) and [documentation routes](docs/README.md)
to find your component. Agents start at [AGENTS.md](AGENTS.md).

For issue work, read the [slice workflow](docs/development/slice-workflow.md),
then use [GitHub conventions](docs/development/github-workflow.md) for issues,
branches, commits, PRs, Projects tracking, and cleanup. The optional
[CLI tutorial](docs/development/git-github-cli-workflow-tutorial.md) provides
command examples in workflow order.

## While Working

- Use the workflow's [activity route](docs/development/slice-workflow.md#reading-route)
  for planning, design review, implementation, verification, and handoffs.
- Find durable documentation owners in the [documentation index](docs/README.md#documentation-maintenance).
- Use the component's documented checks and record evidence under
  [verification](docs/development/slice-workflow.md#verification-and-delivery-status).
- Follow the repository's [scope, branch, and secret protections](AGENTS.md#essential-rules).

## Prepare Review

Use [Conventional Commits](docs/development/conventional-commits.md) and the
[PR template](.github/PULL_REQUEST_TEMPLATE.md). Follow
[PR conventions](docs/development/github-workflow.md#pull-requests) and the
workflow's [publication, integration](docs/development/slice-workflow.md#publication-and-integration),
and [completion conditions](docs/development/slice-workflow.md#whole-issue-completion).
